# Формат пакета Астролябии (схема v2)

Пакет это данные, хаб это движок. Любой может собрать свой пакет из исходников по этой схеме.

## Исходники: `packs/src/<pack>/`

```
pack.json            метаданные: id, version, title, description, license, grades[], credits[]
G0/<topic>.json      темы ядра грейда (одна тема = один файл)
S0/<topic>.json      темы эпохи без эволюции (gate: none), у каждой есть probe
R1/levels.json       область: id, title, levels[{level, hours, to_grade, check}]
R1/<L>-<topic>.json  темы уровня области (A, B, C, PII)
```

Тема: `id`, `order`, `title{ru,en}`, `goal{ru,en}`, `criteria{ru[],en[]}`, `materials[]`, при необходимости `own_texts[]`, `refs[]`, `minutes_by_track{}`, `minutes_total`. Тема ядра несёт `grade`; тема области несёт `area`, `level`, `to_grade`.

Грейд с `gate: "none"` не имеет экзамена и `checks`: он никогда не запирает следующий грейд, а каждая его тема несёт `probe`, которую хаб выполняет сам вместо проверки наставником: `hub` (хаб запущен), `node` (Node 22.13+), `git` (`git --version` в PATH), `agent` (выбранный CLI найден) или `manual` (галочка). В пакете так устроена эпоха I, настройка рабочего места. Интерфейс не показывает коды грейдов (`S0`, `G0`): эпохи нумеруются по `order`.

Материал, 7 обязательных полей рубрики плюс происхождение: `kind` (understand | do), `type` (docs | course | video | paper | repo | book | article | notebook | report | tool), `access` (free | freemium | paid), `date` (YYYY-MM, YYYY или null) и `classic`, `minutes`, `lang`, `checked_at`, `closes{ru,en}` и `criteria[]`, `source` (web | channel:<канал>/<пост> | catalog), `terms` (лицензия или условия). Необязательно `track` (python | typescript | k6 | locust и т.п.).

Правила, которые проверяет `npm run check:pack`:
- у темы есть хотя бы один `understand` и один `do` (материал или свой текст);
- каждый критерий закрыт хотя бы одним материалом, своим текстом или `refs`;
- `refs` указывают на существующую тему и её критерий;
- `order` уникален внутри грейда или уровня, у каждого уровня есть темы, у каждого грейда есть ядро;
- `probe` допустима только в грейде с `gate: none`, и у каждой темы такого грейда она есть; `checks` у него нет;
- `minutes_total` равен сумме минут (или максимуму по трекам);
- в исходниках нет roadmap.sh и YouTube;
- канал в `source` обязан быть в `credits` пакета (согласие автора).

## Сборка: `npm run build:pack`

`tools/build-pack.ts` обходит темы в порядке изучения: ядро G0, затем уровни областей с `to_grade: G0` (по номеру области, затем уровню), затем G1 и так далее. Каждой теме даётся `key` (`G0/tokens-context`, `R1/A-git-basics`) и сквозной `seq`.

Повторы: первая встреча URL изучается, в следующих темах материал получает `repeat_of: {topic, title}`, и хаб показывает сноску «вы это уже проходили, стоит повторить». `refs` получают `title` целевой темы. Часы грейда = `hours_core` + сумма часов привязанных уровней.

Результат: `packs/<pack>.json` (проверяется по `packs/schema/pack.schema.json`) и `packs/<pack>.credits.md` (каналы с согласием и домены источников).

## Проверки экзамена: `checks`

У каждого грейда в `pack.json` есть `checks: {ru: [...], en: [...]}`, от 5 до 8 коротких утверждений, одинаковых по числу и порядку в обоих языках. Это рубрика экзамена грейда: каждое утверждение проверяющий должен подтвердить одним путём к файлу и одной точной цитатой из папки ученика. Идентификатор пункта в экзамене: `G0#1`, `G0#2` и так далее по порядку. Экзамен сдан только когда по всем пунктам есть вердикт `pass`, и хаб механически нашёл цитату в файле. Предложение `exam` остаётся постановкой задачи для ученика. `tools/check-pack.ts` проверяет наличие, число (5–8) и совпадение длин ru и en.

## Лицензия

Тексты пакета (темы, критерии, свои тексты) под CC BY-SA 4.0. Чужие материалы остаются у авторов на их условиях, в пакете только ссылки и поле `terms`.
